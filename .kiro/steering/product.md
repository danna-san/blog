# プロダクト概要（product）

## 何を作るか

GitHub の機能だけで動く「Issue から書く日記ブログ」。

1. 書き手は GitHub Mobile などから Issue を作り、その日の出来事をメモと写真で残す。
2. 毎朝 6:00（JST）に GitHub Actions が前日分の Issue をまとめ、Claude が書き手本人の文体で日記に仕上げる。
3. 仕上がった記事は `YYYY-MM-DD.html` として GitHub Pages で公開される。

## 大事にすること（優先順）

1. **人が書いた日記として自然に読めること。** AI が組み立てたと読者に感じさせない。文体は書き手ごとの設定ファイルで決める。
2. **書かれていないことを足さないこと。** 出来事・感想・写真の内容を作らない。
3. **GitHub 無料プランだけで完結すること。** 外部 SaaS や有料サーバーを使わない（AI は書き手の Claude サブスクリプションを使い、失敗時は GitHub Models の無料枠に切り替える）。
4. **安全であること。** 公開リポジトリで運用する前提で、秘密情報が漏れない、他人が操作できない、依存ライブラリから脆弱性が入らない。
5. **フォークしてすぐ使えること。** 記事を消し、`blog.config.json` と `config/` を書き換えれば、別の人のブログとして使い始められる。

## 利用者

- **書き手**（リポジトリ所有者）: スマホで Issue を書くだけ。HTML や Git の操作はしない。
- **読者**: ブログを読む。リポジトリは見ない前提だが、見られても困らない運用にする。
- **フォークする人**: テンプレートと文体設定だけを変えて使い始める。

## やらないこと（現時点）

- コメント欄、アクセス解析、外部の検索サービス
- 記事ごとの PR レビューによる公開（毎朝自動で直接公開する。必要になったら仕様を追加する）
- AI による写真の内容説明（写真は見せるだけで、文章では描写しない）

## 公開リポジトリであることの前提

GitHub Pages を無料で使うためリポジトリは公開する。元の Issue（メモ・写真）、ワークフロー、文体設定は誰でも見られる。これは書き手が了承済み。目立たなくする工夫として、Issue に自動コメントを残さず、自動コミットの作者を書き手本人の名前にする。
